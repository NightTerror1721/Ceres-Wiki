# La CLI de `ceres`

`ceres` es la herramienta de la máquina: ensambla, enlaza, archiva, ejecuta, desensambla,
perfila y depura programas Ceres.

## Invocación general

```
ceres <comando> <fichero> [opciones]
ceres <fichero>              # atajo de "ceres run <fichero>"
```

El **primer token** elige el comando si es uno de los de abajo; si no, se toma como el fichero
de entrada y el comando es **`run`**.

<Include file="_ceres-commands.mdx" />

<Callout type="warn" title="Detalles sorprendentes">
- **No hay `--version`.**
- `-h`/`--help` (y sin argumentos) imprime el uso a **stderr** y sale con estado **2** — no es un
  error.
- La salida del programa **no** va a este terminal: va al **terminal virtual** de la máquina
  (ver [El terminal virtual](/wiki/maquina-terminal)).
- Un fichero cuya extensión es exactamente `.cres` se carga como binario; cualquier otro
  (`.casm`, `.txt`, ninguno) se ensambla como fuente CASM.
</Callout>

## Las opciones de máquina

Todo comando que arranca una máquina (`run`, `profile`, `debug`) admite estas. Cada una parte
del perfil elegido y lo convierte en `custom`.

<Include file="_ceres-machine.mdx" />

## `run`

<Include file="_ceres-run.mdx" />

```shell
> ceres run hello.cres
> ceres run game.cres --profile retro --disk save.img
> ceres run game.casm --port 0=stick.img --cart 1=game.cart
> ceres run shell.casm --host-dir ./sandbox -- --verbose input.txt
> ceres run fb.casm --headless --screen-log frames.txt
> ceres run            # sin programa: arranca la shell
```

<Callout type="info" title="¿Ventana o no?">
Con un build SDL y sin `--headless`, la ventana se abre **en el primer fotograma presentado**;
`--window` hace que una ventana que no se pueda abrir sea un error; `--headless` (o
`CERES_HEADLESS`) no abre ninguna. Sin programa, `run` arranca la **shell** (ver
[La shell](/wiki/maquina-shell)).
</Callout>

## `asm`, `link`, `ar`

```
ceres asm <fuente.casm>... [-o <salida.cres>] [--listing] [--json] [--debug] [--emit-debug-json] [-c]
ceres link <fichero.cobj|fichero.car>... -o <salida.cres> [--debug] [--symtab] [--gc-sections]
ceres ar <salida.car> <fichero.cobj>...
```

- `asm` con varias fuentes las ensambla y enlaza juntas; sin `-o` valida (no hace falta `main`);
  con `-c` produce un `.cobj`.
- `link` necesita `-o` y un `main`; con `--gc-sections`, un miembro se arrastra solo si resuelve
  un nombre que nada más define, y las funciones inalcanzables se descartan.
- `ar` empaqueta objetos (y reempaqueta `.car`) en un archivo.

```shell
> ceres asm examples/main.casm -o hello.cres
> ceres asm lib.casm -o lib.cobj -c
> ceres link main.cobj lib.car -o prog.cres --debug --symtab
> ceres ar libstuff.car strings.cobj math.cobj
```

## `disasm`, `profile`, `debug`

```
ceres disasm <fichero.casm|fichero.cres> [--debug]
ceres profile <fichero.casm|fichero.cres> [<máquina>]
ceres debug <fichero.casm|fichero.cres> [<fuente2.casm> ...] [<máquina>]
                          [--no-stop-on-entry] [--server] [--no-history]
```

- `disasm` muestra dirección, palabra cruda e instrucción; `--debug` anota cada palabra con tu
  `fichero:línea`.
- `profile` informa de instrucciones y **ciclos** por función y por línea (un `.cres` sin
  información de depuración se rechaza: ensambla con `--debug`).
- `debug` es el depurador interactivo; `--server` habla NDJSON en vez de un REPL. Ver
  [El depurador](/wiki/cli-debugger).

## Códigos de salida

| Situación | Código |
| --- | --- |
| Éxito (`asm`, `link`, `ar`, `disasm`, `profile`) | 0 |
| Error de uso, `-h`/`--help`, sin args, opción desconocida | 2 |
| Fichero no encontrado, fallo de ensamblado/enlace/ejecución | 1 |
| `run` completado | El estado que pide el programa (sus 8 bits bajos) |

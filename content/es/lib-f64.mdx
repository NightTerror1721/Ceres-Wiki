# El double de software

La máquina tiene coma flotante de 32 bits. Cuando necesitas la precisión de un `double` de
verdad, Ceres trae **binary64 en software**.

## Dos formas de usarlo

**1. Compilando con `--soft-double`.** El compilador convierte `double` en un binary64 real
y llama a las rutinas de `ceres/f64.h` en cada operación:

```shell
> ceresc prog.c build/lib/O2/libceres.car --decls ... -I include -O2 --soft-double --run
```

```c
double x = 1.0 / 3.0;
printf("%.17g\n", x);        // 0.33333333333333331
```

**2. Llamando a la API directamente**, sin tocar el compilador:

```c
#include "ceres/f64.h"

f64 a = __f64_from_i32(1);
f64 b = __f64_from_i32(3);
f64 c = __f64_div(a, b);
printf("%llx\n", (unsigned long long)c);   // 3FD5555555555555
```

## La API

```c
typedef unsigned long long f64;     // los bits crudos de un binary64

f64 __f64_add(f64, f64);
f64 __f64_sub(f64, f64);
f64 __f64_mul(f64, f64);
f64 __f64_div(f64, f64);
f64 __f64_sqrt(f64);
f64 __f64_neg(f64);
int __f64_cmp(f64, f64);            // -1, 0, 1; 2 si alguno es NaN

f64   __f64_from_f32(float);        // exacto
float __f64_to_f32(f64);            // redondeado
f64   __f64_from_i32(int);  f64 __f64_from_u32(unsigned int);
f64   __f64_from_i64(long long);  f64 __f64_from_u64(unsigned long long);
int   __f64_to_i32(f64);  long long __f64_to_i64(f64);
```

<Callout type="info" title="Semántica IEEE completa">
Redondeo a par, subnormales, ±infinito, ±0 y NaN. El resultado NaN es el NaN silencioso
`0x7FF8000000000000` salvo que un operando fuera NaN, cuyo *payload* se conserva.
Convertir a entero trunca hacia cero y satura al extremo si se sale de rango.
</Callout>

## Qué puedes hacer con un `double`

Con `--soft-double` funcionan suma, resta, multiplicación, división, comparaciones,
condiciones, conversiones, `++`/`--`, y pasarlo/retornarlo por valor. **No** funcionan
`%`, los operadores de bits ni los desplazamientos sobre `double` (dan `E5002`), y no hay
`sqrt`/`fmod` de `double` por operador.

```c
double suma_serie(int n)
{
    double s = 0.0;
    for (int i = 1; i <= n; i++)
        s += 1.0 / (double)i;      // cada suma es una llamada a __f64_add
    return s;
}
```

## Impresión y lectura exactas

Con `--soft-double`, `printf` (`%f %e %g %a`), `scanf` (`%lf`) y `strtod` usan un motor de
conversión decimal **exacto** con enteros grandes (`src/fconv64.c`), no una aproximación.
`ftoa_shortest` sólo existe para `float`, pero `%g` con 17 dígitos basta para un `double`.

```c
double d = 0.1;
printf("%.20f\n", d);      // 0.10000000000000000555
```

## `strfromf` (C23) y `ftoa_shortest`

```c
#include "stdlib.h"

char buf[32];
strfromf(buf, sizeof buf, "%.3f", 3.14159f);   // "3.142"
ftoa_shortest(buf, sizeof buf, 0.1f);          // "0.1"
```

## ¿Cuándo merece la pena?

| Situación | Recomendación |
|---|---|
| Juego (posiciones, física sencilla) | `float` y `ceres/fixed.h` |
| Dinero, cálculos acumulativos | `--soft-double` |
| Portar código que usa `double` | `--soft-double` |
| Máximo rendimiento | `float` (una instrucción por operación) |

<Callout type="warn" title="Cuesta una llamada por operación">
Un binary64 en software es correcto pero **lento**. No lo uses para el bucle de dibujo:
reserva `double` para lo que de verdad necesita precisión (acumuladores, física de
precisión, formato de resultados).
</Callout>

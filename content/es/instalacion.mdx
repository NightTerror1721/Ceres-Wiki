# Instalar Ceres

Para compilar y ejecutar programas Ceres necesitas tres cosas:

| Pieza | Herramienta | De |
| --- | --- | --- |
| La máquina y sus herramientas | `ceres` | CeresASM |
| El compilador de C | `ceresc` | Ceres-C |
| La librería estándar | `stdlib/` | Ceres STDLIB |

Hay dos formas de conseguirlas.

<Cards>
  <Card title="Instalar un paquete" icon="📦" href="/wiki/instalar-paquete">Descarga un paquete ya hecho (Windows, Linux, macOS) y ejecuta el instalador.</Card>
  <Card title="Construir desde el código" icon="🛠️" href="/wiki/construir-ceres">Clona CeresBinaries y constrúyelo entero, o construye los tres repositorios a mano.</Card>
</Cards>

## Cómo se encuentran las herramientas

<Callout type="info" title="Cómo localizan ceresc y los scripts las herramientas">
`ceresc` encuentra `ceres` en este orden: **`--ceres-path`**, el directorio **`CERES_PATH`**
(donde está instalado Ceres), luego el **`PATH`**. Las variables de entorno con el nombre de una
herramienta — **`CERES`**, **`CERESC`** — toman el ejecutable o su directorio. Los scripts de la
librería siguen la misma regla.
</Callout>

## Si tienes un paquete

Tras instalar (o descomprimir) un paquete, un solo comando compila y ejecuta un programa contra la
librería estándar, sin pasar rutas:

```shell title="Compilar y ejecutar contra la librería instalada"
> ceresc prog.c --stdlib -O2 --run
```

`--stdlib` compila contra la librería donde está instalado Ceres: `stdlib/include` entra en la
búsqueda de includes y, con `--run`, se enlaza `libceres` y `stdlib/lib` entra en la búsqueda de
`-l` (`-lceres_irq`, …).

## Si trabajas en la propia librería

Construyes la librería una vez por nivel de optimización (`-O0`, `-O1`, `-O2`) en
`build/lib/O*/libceres.car`, con un fichero de declaraciones al lado:

```shell title="Construir toda la librería"
> make                 # o, directamente:
> powershell -File tools/mklib.ps1
```

Luego pasas el archivo y sus declaraciones explícitamente:

```shell title="Compilar y ejecutar contra un build local"
> ceresc prog.c build/lib/O2/libceres.car --decls build/lib/O2/libceres.decls.casm -I include -O2 --run
```

<Callout type="warn" title="Módulos opcionales: hay tres">
Tres módulos enganchan vectores de interrupción, y el enlazador permite **un dueño por vector**:
`irq` (temporizador, alarma), `fault` (informes de fallo) y `mmu` (fallos de página). Un programa
pide uno con una línea al principio:

```c
// USE: mmu
```

Un programa que instala su propio manejador de vector **no** debe enlazarlos.
</Callout>

# Keyboard, mouse and gamepad

For a game you want to know not only "which keys are held" but "what changed since the
previous frame". `ceres/input.h` consolidates **keyboard, mouse and gamepad** into one
per-frame state.

## The input loop

```c
#include "ceres/input.h"

input_init();
for (;;) {
    input_update();                     // ONCE per frame: drains the devices

    if (key_pressed(KEY_SPACE)) jump();
    if (key_down(KEY_LEFT))     x -= 2;
    if (key_released(KEY_FIRE)) release();

    /* mouse and gamepad */
}
```

`input_update` computes the edges: a key that goes down and up between two updates counts as
*pressed* that frame (a quick tap is not lost), even though `key_down` says it is no longer
held.

## Keyboard

```c
key_down(scancode)       // held now
key_pressed(scancode)    // went down since the previous update
key_released(scancode)   // went up since the previous update
key_any_pressed()        // the first scancode that went down this frame, or 0
key_to_ascii(sc, shift)  // character for a key (0 if it has none)
```

The codes are in `ceres/keys.h` (`KEY_A`…`KEY_Z`, `KEY_LEFT`, `KEY_F1`, `KEY_SPACE`…). The
machine uses USB HID standard scancodes.

<Callout type="tip" title="Without a window: terminal fallback">
With a normal `ceres run` there is no window and the keyboard device receives nothing. With
`input_terminal_fallback(1)`, `input_update()` also reads the terminal and turns each
character into a one-frame press. Your game written against `key_pressed()` runs in a
terminal unchanged.
</Callout>

## Mouse

```c
mouse_pos_x();  mouse_pos_y();          // absolute position
mouse_move_x(); mouse_move_y();         // movement this frame
mouse_scroll();                          // wheel
mouse_btn_down(MOUSE_BTN_LEFT);          // any button of the mask, held
mouse_btn_pressed(mask);
mouse_btn_released(mask);
```

Buttons: `MOUSE_BTN_LEFT`, `MOUSE_BTN_RIGHT`, `MOUSE_BTN_MIDDLE`.

## Gamepad

```c
pad_down(GP_BTN_SOUTH);                // ALL buttons of the mask, held
pad_pressed(GP_BTN_EAST);              // ANY of them went down this frame
pad_released(mask);
pad_axis(PAD_AXIS_LEFT_X);             // -1.0..1.0 with a dead zone
```

Axes: `PAD_AXIS_LEFT_X/Y`, `PAD_AXIS_RIGHT_X/Y`, `PAD_AXIS_LEFT_TRIGGER`,
`PAD_AXIS_RIGHT_TRIGGER`. Buttons: `GP_BTN_SOUTH/EAST/WEST/NORTH`, `GP_BTN_DPAD_*`,
`GP_BTN_START/BACK`, shoulders, sticks.

## Reading real keystrokes (menus, text fields)

`input_update` is for a frame loop. To read **what a person types, one press at a time**
(menus, typing a name), use `ceres/key.h`:

```c
#include "ceres/key.h"

key_start();
for (;;) {
    int k = key_wait();                  // wait for one press
    if (k == KEYC_ESCAPE) break;
    if (k == KEYC_UP) { /* ... */ }
    if (k == 'q') break;
}
key_stop();                              // give the terminal back to line mode
```

A **keystroke** is an `int`: a typed character is its code point (an accented letter is one
value), and a key that types no character is a `KEYC_*` constant far above them.
`key_get()` is the non-blocking version (`KEYC_NONE` if there is nothing).

<Callout type="warn" title="Do not mix key_wait with scanf/fgets without key_stop">
While raw keys are active, the terminal does not edit lines. Call `key_stop()` before going
back to `scanf()` or `line_read()`. The host also restores the terminal when the program
ends.
</Callout>

## A pattern: key state for two players

```c
static int read_player(int up, int down, int left, int right)
{
    if (key_down(left))  x--;
    if (key_down(right)) x++;
    if (key_down(up))    y--;
    if (key_down(down))  y++;
}
```

Key codes also accept `key_down(KEY_W)` as well as the arrows, for classic control schemes.

# Text framebuffer

The **text framebuffer** is a grid of characters your program draws into and then shows. It
is not a scrolling console: it is a board redrawn whole, ideal for text games, roguelikes
and menus.

## Init it

```c
#include "ceres/text.h"

if (text_init(40, 20) != 0)     // columns, rows (up to 200x100)
{
    puts("no screen");
    return 1;
}
text_shutdown();
```

## Drawing

```c
text_clear(' ');                 // fill the grid
text_put(x, y, '@');             // one cell
text_text(x, y, "Hello ñandú");  // UTF-8; '\n' drops a row
text_printf(x, y, "HP %d", hp);  // formatted
text_hline(x, y, len, '-');
text_vline(x, y, len, '|');
text_rect(x, y, w, h, '#');      // outline
text_fill(x, y, w, h, '.');
text_box(x, y, w, h);            // frame with + - |
text_copy(dx, dy, sx, sy, w, h); // copy a region
text_scroll(1);                  // scroll up one row
text_present();                  // show the frame
```

## Per-cell colour

Each cell has a colour attribute (one byte). `0` means the terminal's own colours.

```c
text_set_attr(TEXT_ATTR(TEXT_BRIGHT + TEXT_YELLOW, TEXT_BLACK));
text_text(1, 1, "Title");

text_put_attr(10, 10, '@', TEXT_ATTR(TEXT_WHITE, TEXT_BLUE));   // one cell with its own
unsigned char a = text_get_attr(10, 10);
```

Colours: `TEXT_BLACK TEXT_RED TEXT_GREEN TEXT_YELLOW TEXT_BLUE TEXT_MAGENTA TEXT_CYAN TEXT_WHITE`, plus
`TEXT_BRIGHT` to add brightness. `TEXT_ATTR(fg, bg)` packs them.

## Where does the frame go?

The plane is always drawn by the **GPU** (the text plane of V0). With a window (SDL) you see it
on screen; without one (`--headless`) it is still composited and the host can capture it:

```bash
ceres run rogue.cres --headless --screen-log frames.txt   # the plane as text at every Present
ceres run rogue.cres --frames shots/                      # a PNG per frame
```

The grid size is queried at run time:

```c
int cols = text_cols();
int rows = text_rows();
```

## An example: a minimal roguelike

```c title="rogue.c"
// USE: irq
#include "stdio.h"
#include "ceres/text.h"
#include "ceres/key.h"
#include "ceres/rand.h"

#define W 40
#define H 20

static char map[H][W];
static int px = W / 2, py = H / 2;

static void generate(void)
{
    struct rng r;
    rng_seed(&r, 1234);
    for (int y = 0; y < H; y++)
        for (int x = 0; x < W; x++)
            map[y][x] = (x == 0 || y == 0 || x == W - 1 || y == H - 1)
                       ? '#' : (rng_chance(&r, 12) ? '#' : '.');
    map[py][px] = '.';
}

static void draw(void)
{
    for (int y = 0; y < H; y++)
        for (int x = 0; x < W; x++)
            text_put(x, y, map[y][x]);
    text_put(px, py, '@');
    text_printf(0, 0, "pos %d,%d", px, py);
    text_present();
}

int main(void)
{
    if (text_init(W, H) != 0) return 1;
    generate();
    key_start();
    for (;;)
    {
        draw();
        int k = key_wait();
        if (k == KEYC_ESC || k == 'q') break;
        int nx = px, ny = py;
        if (k == KEYC_UP || k == 'w')    ny--;
        if (k == KEYC_DOWN || k == 's')  ny++;
        if (k == KEYC_LEFT || k == 'a')  nx--;
        if (k == KEYC_RIGHT || k == 'd') nx++;
        if (map[ny][nx] != '#') { px = nx; py = ny; }
    }
    key_stop();
    text_shutdown();
    return 0;
}
```

<Callout type="tip" title="The framebuffer and the keys">
In a window the keys arrive on the keyboard device; in a terminal, the first call to
`key_start()` asks the host to deliver them as they are pressed. The **`irq`** module is not
needed for `key_wait()`: it blocks on the device.
</Callout>

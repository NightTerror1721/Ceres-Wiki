# Installing and building

You need three things: the **compiler** (`ceresc`), the **machine** (`ceres`) and this
**standard library**. On a development machine the three repositories usually sit as
siblings:

```
Projects/
├─ CeresASM/        → ceres.exe comes from here
├─ Ceres-C/         → ceresc.exe comes from here
└─ Ceres Projects/
   └─ Ceres STDLIB/ → this library
```

## 1. Check the tools

<Callout type="info" title="Finding the binaries">
The library scripts look for `ceresc`/`ceres` next to the checkout (`../../Ceres-C`,
`../../CeresASM`) or through the **`CERESC`** and **`CERES_PATH`** environment variables.
</Callout>

```shell title="Check they are on the PATH"
> ceresc --version
> ceres --help
```

## 2. Build the library

The library is built **once per optimization level** (`-O0`, `-O1`, `-O2`) into
`build/lib/O*/libceres.car`, alongside a declarations file.

```shell title="Build the whole library"
> make                 # or, directly:
> powershell -File tools/mklib.ps1
```

<Output title="What you will see when it finishes">
-O0 : compiling 100 C files
-O0 : assembling 107 units
build/lib/O0/libceres.car: 107 objects, ... bytes
... (repeated for -O1 and -O2)
done
</Output>

## 3. Build and run a program

The compiler does everything: it preprocesses, compiles, assembles, links against the
library archive and **runs** with `--run`. Only your program is compiled; the library comes
from the `.car`.

```shell title="Build and run against the library"
> ceresc prog.c build/lib/O2/libceres.car --decls build/lib/O2/libceres.decls.casm -I include -O2 --run
```

The three key arguments are:

| Argument | What it is for |
|---|---|
| `build/lib/O2/libceres.car` | The library archive (only what you use is linked) |
| `--decls build/lib/O2/libceres.decls.casm` | The declarations of what the library defines |
| `-I include` | Where the headers live (`stdio.h`, `ceres/gfx.h`, …) |

## 4. Use the library in a project

For your own project just call `ceresc` with those arguments. There is a ready-made example
for each demo:

```shell title="Run a library example"
> tools\example.ps1 hello
> tools\example.ps1 snake          # opens a window
> tools\example.ps1 snake --headless
```

<Callout type="warn" title="Optional modules are requested with // USE:">
Two modules bind interrupt vectors and the linker allows **one owner per vector**: `irq`
(alarm, pausing game loop) and `fault` (fault reports). A program that wants them asks for
one with a line at the top:

```c
// USE: irq
```

A program that installs its own vector handler must **not** link them.
</Callout>

## 5. Useful compiler options

| Option | Effect |
|---|---|
| `-O0` / `-O1` / `-O2` | Optimization level (`-O1` is the default) |
| `-Os` / `-Og` | Optimize for size / for debugging |
| `-Werror` | Turn warnings into errors |
| `-S` | Stop at assembly (`.casm`), do not link |
| `--emit-ir` | Print the optimized IR |
| `-fshort-double` | Make `double` a `float` (binary32) |
| `--` | Everything after this goes to your program |
| `--stats` | Count instructions, inlining and jump tables |

<Callout type="tip" title="-fshort-double">
By default `double` is **native binary64** (register pairs). With `-fshort-double` the
compiler makes `double` a `float` (binary32): faster, less precise.
</Callout>

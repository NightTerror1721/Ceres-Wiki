# Installing Ceres

To build and run Ceres programs you need three things:

| Piece | Tool | From |
| --- | --- | --- |
| The machine and its tools | `ceres` | CeresASM |
| The C compiler | `ceresc` | Ceres-C |
| The standard library | `stdlib/` | Ceres STDLIB |

There are two ways to get them.

<Cards>
  <Card title="Install a package" icon="📦" href="/wiki/instalar-paquete">Download a ready-made package (Windows, Linux, macOS) and run the installer.</Card>
  <Card title="Build from source" icon="🛠️" href="/wiki/construir-ceres">Clone CeresBinaries and build the whole thing, or build the three repositories by hand.</Card>
</Cards>

## How the tools find each other

<Callout type="info" title="How ceresc and the scripts locate the tools">
`ceresc` finds `ceres` in this order: **`--ceres-path`**, the **`CERES_PATH`** directory (where
Ceres is installed), then **`PATH`**. The environment variables named after a tool — **`CERES`**,
**`CERESC`** — take the executable or its directory. The library scripts follow the same rule.
</Callout>

## If you have a package

After installing (or unpacking) a package, one command builds and runs a program against the
standard library, with no paths to pass:

```shell title="Build and run against the installed library"
> ceresc prog.c --stdlib -O2 --run
```

`--stdlib` compiles against the library where Ceres is installed: `stdlib/include` joins the
include search, and with `--run` `libceres` is linked and `stdlib/lib` joins the `-l` search
(`-lceres_irq`, …).

## If you work on the library itself

You build the library once per optimization level (`-O0`, `-O1`, `-O2`) into
`build/lib/O*/libceres.car`, with a declarations file beside it:

```shell title="Build the whole library"
> make                 # or, directly:
> powershell -File tools/mklib.ps1
```

Then you pass the archive and its declarations explicitly:

```shell title="Build and run against a local build"
> ceresc prog.c build/lib/O2/libceres.car --decls build/lib/O2/libceres.decls.casm -I include -O2 --run
```

<Callout type="warn" title="Optional modules — there are three">
Three modules bind interrupt vectors, and the linker allows **one owner per vector**: `irq`
(timer, alarm), `fault` (fault reports) and `mmu` (page faults). A program asks for one with a
line at the top:

```c
// USE: mmu
```

A program that installs its own vector handler must **not** link them.
</Callout>

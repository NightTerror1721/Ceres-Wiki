# The `ceresc` CLI

`ceresc` is the **Ceres-C compiler**: it reads C (and `.casm` sources) and produces CASM text,
or - with `--run` - assembles, links and runs the program on the machine.

## Invocation

```
ceresc <file.c|file.casm|file.cobj|file.car>... [-o <output>] [options]
```

The inputs are C sources (compiled), CASM sources (assembled), `.cobj` objects and `.car`
archives (linked as they are).

## The `--stdlib` flow

`ceresc prog.c --stdlib -O2 --run` compiles against the C library where Ceres is installed:
`CERES_PATH/stdlib/include` joins the include search, and with `--run` `libceres` is linked and
`stdlib/lib` joins the `-l` search.

```shell
> ceresc hello.c --stdlib -O2 --run          # compile, link and run, in one go
> ceresc hello.c --stdlib -O2 -o hello.cres  # just link the program
```

<Callout type="info" title="Where is Ceres?">
`ceresc` finds `ceres` and the library in `--ceres-path`, then `CERES_PATH`, then beside itself,
then `PATH` (for `ceres`). See [Installing a package](/wiki/instalar-paquete).
</Callout>

## The split pipeline

To keep the pieces, use `-S` (compile to CASM) and let `ceres` assemble and link:

```shell
> ceresc prog.c --stdlib -I include -O2 -S -o prog.casm
> ceres asm -c prog.casm -o prog.cobj
> ceres link prog.cobj libceres.car -o prog.cres
```

With the split pipeline, pass the library's declarations to `ceresc` (`--decls`) and the archive
to `ceres link`. See [Separate compilation](/wiki/build-toolchain).

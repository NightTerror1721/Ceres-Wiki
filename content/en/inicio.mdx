# Welcome to Ceres

**Ceres** is a 32-bit virtual machine with its own processor, I/O devices, a C compiler and
a complete standard library. This wiki takes you from `Hello, world` to full retro games,
covering **every** module along the way.

<Callout type="tip" title="What you will build">
By the end you will know how to write, build and debug Ceres programs: console programs
first, then graphics, sound, files and crash-safe saves, and finally **Pong**,
**Arkanoid**, **Connect Four**, **Sokoban** and a **2D RPG adventure** with levels.
</Callout>

## The three pieces

Ceres is not a standalone library: it is **three projects that fit together**.

| Project | What it is | What it gives you |
|---|---|---|
| **CeresASM** | The virtual machine | 32-bit processor, 183 instructions, MMIO devices, reverse-execution debugger |
| **Ceres-C** | The compiler | C (C89 + `long long` + parts of C11/C23) producing readable assembly |
| **Ceres STDLIB** | The standard library | `stdio`, `stdlib`, `math`, graphics, sound, files, data structures… |

The flow is **C → CASM → object → program**, and the whole environment is
**deterministic**: the machine's clock counts instructions, so the same program does exactly
the same thing on every run.

## The philosophy of the machine

The machine is not "an emulator of an old computer": it is a **coherent, didactic** design
meant to let you follow a single instruction from the C code all the way down to the last
register.

<Callout type="info" title="Determinism">
The tick counter is the number of executed instructions. That is why the library's tests
require a program to print **the same bytes** at `-O0`, `-O1` and `-O2`, and why the
debugger can **rewind** execution.
</Callout>

# The `ceres` CLI

`ceres` is the machine's tool: it assembles, links, archives, runs, disassembles, profiles and
debugs Ceres programs.

## General invocation

```
ceres <command> <file> [options]
ceres <file>              # shorthand for "ceres run <file>"
```

The **first token** selects the command if it is one of the commands below; otherwise it is
taken as the input file and the command is **`run`**.

<Include file="_ceres-commands.mdx" />

<Callout type="warn" title="Surprising details">
- There is **no `--version`.**
- `-h`/`--help` (and no arguments at all) prints usage to **stderr** and exits with status
  **2** - not an error.
- The program's output does **not** go to this terminal: it goes to the machine's **virtual
  terminal** (see [The virtual terminal](/wiki/maquina-terminal)).
- A file whose extension is exactly `.cres` is loaded as a binary; any other (`.casm`, `.txt`,
  none) is assembled as CASM source.
</Callout>

## The machine options

Every command that starts a machine (`run`, `profile`, `debug`) takes these. Each one starts
from the chosen profile and turns it into `custom`.

## `run`

<Include file="_ceres-run.mdx" />

```shell
> ceres run hello.cres
> ceres run game.cres --profile retro --disk save.img
> ceres run game.casm --port 0=stick.img --cart 1=game.cart
> ceres run shell.casm --host-dir ./sandbox -- --verbose input.txt
> ceres run fb.casm --headless --screen-log frames.txt
> ceres run            # no program: starts the shell
```

<Callout type="info" title="Window or not">
With an SDL build and no `--headless`, the window opens **on the first presented frame**;
`--window` makes a window that cannot be opened an error; `--headless` (or `CERES_HEADLESS`)
opens none. Without a program, `run` starts the **shell** (see [The shell](/wiki/maquina-shell)).
</Callout>

## `asm`, `link`, `ar`

```
ceres asm <source.casm>... [-o <out.cres>] [--listing] [--json] [--debug] [--emit-debug-json] [-c]
ceres link <file.cobj|file.car>... -o <out.cres> [--debug] [--symtab] [--gc-sections]
ceres ar <output.car> <file.cobj>...
```

- `asm` with several sources assembles and links them together; without `-o` it validates (no
  `main` needed); with `-c` it produces one `.cobj`.
- `link` needs `-o` and a `main`; with `--gc-sections`, a member is pulled in only if it
  resolves a name nothing else defines, and unreachable functions are dropped.
- `ar` packs objects (and repacks `.car`s) into an archive.

```shell
> ceres asm examples/main.casm -o hello.cres
> ceres asm lib.casm -o lib.cobj -c
> ceres link main.cobj lib.car -o prog.cres --debug --symtab
> ceres ar libstuff.car strings.cobj math.cobj
```

## `disasm`, `profile`, `debug`

```
ceres disasm <file.casm|file.cres> [--debug]
ceres profile <file.casm|file.cres> [<machine>]
ceres debug <file.casm|file.cres> [<source2.casm> ...] [<machine>]
                          [--no-stop-on-entry] [--server] [--no-history]
```

- `disasm` shows address, raw word and instruction; `--debug` annotates each word with your
  `file:line`.
- `profile` reports instructions and **cycles** by function and by source line (a `.cres`
  without debug info is rejected: assemble with `--debug`).
- `debug` is the interactive debugger; `--server` speaks NDJSON instead of a REPL. See
  [The debugger](/wiki/cli-debugger).

## Exit codes

| Situation | Code |
| --- | --- |
| Success (`asm`, `link`, `ar`, `disasm`, `profile`) | 0 |
| Usage error, `-h`/`--help`, no args, unknown option | 2 |
| File not found, assemble/link/run failure | 1 |
| `run` completed | The status the program asks for (its low 8 bits) |

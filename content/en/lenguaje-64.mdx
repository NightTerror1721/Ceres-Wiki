# 64-bit and floating point

## 64-bit integers

`long long` is a **real 8-byte type**. Arithmetic, comparisons, bit operations, shifts and
divisions work; the compiler lowers it as a pair of words.

```c
long long big  = 9223372036854775807LL;
long long more = big + 1;             // wraps around (two's complement)
printf("%lld\n", more);
```

The `printf` formats for fixed-width types come from `inttypes.h`:

```c
#include "inttypes.h"
uint64_t nano = 1234567890123ull;
printf("%" PRIu64 "\n", nano);      // "llu" under the hood
```

<Callout type="info" title="Operations rejected with E5002">
A `switch` with a 64-bit discriminant, or passing a `long long` to a one-instruction
builtin, are not supported and give `E5002`. Everything else (add, subtract, multiply,
divide, modulo, bits, compare, convert) works.
</Callout>

## Detecting overflow

```c
#include "stdckdint.h"

long long r;
if (ckd_mul(&r, a, b))
    puts("the product does not fit");
```

For the fast `int` case, the builtins are a handful of instructions:

```c
int r;
if (__builtin_add_overflow(a, b, &r))
    puts("int overflow");
```

## Floating point: first, the uncomfortable truth

The machine has **only 32-bit floating point**. Concretely:

- `float` is IEEE 754 binary32.
- `double` and `long double` **are `float`** (the compiler warns with `W2001`).
- In a variadic call, `float` is **not** promoted to `double`.
- Constants like `3.14159265358979` are rounded to 32 bits.

```c
double d = 1.0 / 3.0;      // actually a float; W2001
```

## The solution: `-fsoft-double`

If you compile with **`--soft-double`**, `double` becomes a **real binary64** implemented in
software (`ceres/f64.h`). The compiler calls `__f64_add`, `__f64_mul`, etc., so it costs one
call per operation, but the precision is that of a real `double`.

```shell
> ceresc prog.c build/lib/O2/libceres.car --decls ... -I include -O2 --soft-double --run
```

```c
double x = 1.0 / 3.0;              // exact binary64
printf("%.17g\n", x);              // 0.33333333333333331
```

With `--soft-double` the constants in `float.h` also become 64-bit (`DBL_MANT_DIG`,
`DBL_MAX`, …), `strtod` returns a real `double`, and `printf`/`scanf` use their own exact
decimal conversion engine.

## Accuracy of `math.h`

The library's math functions are measured:

| Function | Accuracy |
|---|---|
| `sqrt`, `fabs`, `floor`… | one instruction, exact |
| `sin`, `cos` | 1.5 ULP for **every** `float` (Payne–Hanek reduction) |
| `tan` | 2.5 ULP |
| `erf` | 2 ULP |
| `erfc`, `tgamma` | 4 ULP |
| `lgamma` | 3 ULP |

```c
#include "math.h"
printf("%.6f\n", sin(M_PI / 6));   // 0.500000
```

<Callout type="warn" title="Dividing by zero does not fail">
Unless you turn on the IEEE feature, a `float` division by zero does not give `inf`: it
sets the *Trap* flag and leaves the destination unchanged. To change that:

```c
sys_set_features(sys_features() | SYS_FEATURE_IEEE_DIVIDE);
```

Even so, check your divisors: the library does it for you in `fmod`, `sin`, etc.
</Callout>

## Converting between bits and floats

```c
unsigned int bits = float_bits(1.0f);        // 0x3F800000
float         f   = float_from_bits(bits);   // 1.0f
int           kind = fpclassify(f);          // FP_NORMAL
```

There is also an `f64` class (binary64) you can use without `--soft-double`:

```c
#include "ceres/f64.h"
f64 third = __f64_div(__f64_from_i32(1), __f64_from_i32(3));   // 0x3FD5555555555555
```
